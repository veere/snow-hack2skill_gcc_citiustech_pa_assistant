## Context

The codebase supports two deployment modes:
1. **Self-hosted** (`app/serve.py`) — runs locally with `SNOWFLAKE_PAT`, connects via Python connector. Can be tested immediately.
2. **Streamlit in Snowflake** (`app/deploy_sis.py`) — deploys to Snowsight. Requires PUT/COPY via Python connector (same network issue we hit earlier).

Since the Python connector can't reach this Snowflake account from this machine, **SiS deployment won't work** (it uses `snowflake_loader.connect()` for PUT). However, **self-hosted mode** also won't work for the same reason — it connects via the Python connector.

**Viable approach**: Run the existing test suites that exercise the app's core logic directly (grounding, answering, routing, output guard) without needing a running Streamlit server, since they import the modules directly. The `validate_app.py` test does exactly this — it imports `snow`, `grounding`, `answering` and tests all functionality end-to-end against the live Snowflake services.

However, these tests also use `snowflake_loader.connect()` internally. Since that connector can't reach the account, we need to **patch `app/snow.py`** to use `sql_execute` through a different path, OR we can run the tests through a subagent that has `sql_execute` access.

**Better approach**: Deploy via `sql_execute` directly — we can:
1. Create the stage, PUT files, and CREATE STREAMLIT via `sql_execute` (mimicking what `deploy_sis.py` does)
2. Run functional tests by calling the test functions through subagents with `sql_execute` access
